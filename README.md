# PostTrack — упрощённый проект Почты России

Система мониторинга отправки и получения посылок и писем с разделением ролей отправителя, получателя и оператора отделения почтовой связи.

Серверная часть строится как модульный монолит на Kotlin и Ktor. Приложение запускается единым процессом, а данные хранятся в PostgreSQL.

## 1. Назначение системы

* **Для отправителя:** онлайн-оформление отправления и отслеживание посылки.
* **Для получателя:** отслеживание и получение посылки по уникальному идентификатору.
* **Для оператора ОПС:** приём отправлений, организация хранения на складе и выдача получателю.

## 2. Бизнес-логика

### Клиент пользователей

* **Кабинет отправителя:**
  * Калькулятор стоимости доставки с учётом габаритов, веса и способа доставки.
  * Получение штрихкода для сдачи отправления в отделении.
  * Таймлайн прохождения контрольных точек и ожидаемое время прибытия.
* **Кабинет получателя:**
  * Таймлайн прохождения контрольных точек и ожидаемое время прибытия.
  * Уведомления об изменении статуса посылки.
  * Получение кода для выдачи посылки в отделении.

### Клиент оператора

* **Модуль приёмки:**
  * Сверка фактического веса с заявленным при оформлении.
  * Печать почтового ярлыка и перевод отправления в статус `ACCEPTED`.
* **Модуль сортировки и адресного хранения:**
  * Сканирование входящих отправлений.
  * Привязка отправления к физической ячейке кладовой: `Стеллаж X / Полка Y / Ячейка Z`.
* **Модуль выдачи:**
  * Поиск по трек-номеру или номеру телефона получателя.
  * Проверка цифрового кода подтверждения.
  * Отображение складской ячейки и закрытие отправления со статусом `DELIVERED`.

### Клиент службы доставки

* Изменение статуса отправления при прохождении этапов доставки.
* Изменение ожидаемого времени доставки при задержке.

## 3. Структура проекта

```text
app                       запуск и конфигурация Ktor
shared                    общие доменные типы
modules/identity          пользователи и роли
modules/pricing           расчёт стоимости доставки
modules/shipment          жизненный цикл отправления
modules/tracking          события отслеживания
modules/warehouse         хранение и выдача
infrastructure/postgres   подключение к PostgreSQL и миграции Flyway
```

## 4. Запуск

Для запуска приложения и PostgreSQL требуется Docker Compose:

```bash
docker compose up --build
```

После запуска доступны проверки состояния приложения:

* `GET http://localhost:8080/health/live`
* `GET http://localhost:8080/health/ready`

Остановить приложение:

```bash
docker compose down
```

Для удаления контейнеров вместе с локальными данными PostgreSQL:

```bash
docker compose down -v
```

## 5. Локальная сборка

Для локальной сборки требуется JDK 21 или новее:

```bash
./gradlew compileKotlin
```

Результаты сборки сохраняются в корневом каталоге `build/` и группируются по модулям.

Для запуска без Docker необходимо запустить PostgreSQL и задать переменные окружения:

```text
DATABASE_URL=jdbc:postgresql://localhost:5432/posttrack
DATABASE_USER=posttrack
DATABASE_PASSWORD=posttrack
```

После этого приложение можно запустить командой:

```bash
./gradlew :app:run
```
